# Local JSON-RPC matrix (wallet mode)

Default bind: `127.0.0.1:8545` (`--allow-non-loopback` required for LAN; no RPC auth in-process). `latest` / `eth_blockNumber` → **Safe** (≥15 distinct subsequent sealers). Fail-closed: no silent passthrough.

| `eth_call` | Verified (constrained) | Local verified header `n ≤ Safe` (`latest`→Safe). Requires `to` + optional `data`; **no create**, **no state overrides**. Optional EIP-2930 `accessList` is **prefetched** into ProofDb (seed; does not consume `MAX_PROOF_ROUNDS`; ≤32 addresses, ≤64 keys total). Proofs via `eth_getProof` at the requested **hash/number**; execute in **revm**. Unproven SLOAD/account → `-32001` (fail-closed, not zero). `BLOCKHASH` from locally verified headers (`n ≤` executing block in the 256-window); in-window unknown → `-32001`; out-of-window/current → `0` (never `eth_getBlock` from untrusted RPC). Gas cap `min(user, 50_000_000, block gasLimit)`, and from Osaka also EIP-7825's `MAX_TX_GAS` = **16,777,216** — the chain's own per-transaction ceiling, which is the one that binds on a live block. Max **8** proof rounds; calldata ≤ **128 KiB**; at most **32** accounts. Block env comes from the **sealed** header: `TIMESTAMP`, `COINBASE`, `GASLIMIT`, `PREVRANDAO` (BSC's `mixHash`), `BASEFEE`, and `BLOBBASEFEE` from `excessBlobGas`. The blob price uses the Cancun `UpdateFraction` (3338477), which is exact for BSC at every fork — v1.7.8 aliases `DefaultPragueBlobConfigBSC` and `DefaultOsakaBlobConfigBSC` to `DefaultCancunBlobConfig`. Revert / Halt → JSON-RPC **code 3** (geth), not `-32001`. **Chain precompiles the local EVM lacks → `-32001`.** The EVM spec follows the executing block's timestamp, and this boundary is *derived* from revm's own table for that spec rather than kept as a second hand-maintained list — which is how it went stale the first time. On a live (Osaka) block revm covers `0x01..=0x11`, BLS12-381 included. What stays refused is `0x0100` `p256Verify` and BSC's own `0x64` `tmHeaderValidate` / `0x65` `iavlMerkleProofValidatePlato` / `0x66` `blsSignatureVerify` / `0x67` `cometBFTLightBlockValidateHertz` / `0x68` `verifyDoubleSignEvidence` / `0x69` `secp256k1SignatureRecover`. Those used to fall through as ordinary accounts — whose proof verifies as *empty* — so a `CALL` succeeded and returned nothing. Refused instead. Never proxied to upstream `eth_call`. EIP-1898 object block ids → `-32602`. |

| `eth_getTransactionReceipt` | Verified (consensus fields) | No flag needed for a mined receipt. Query hash must be 32 bytes (`-32602`). Upstream `blockHash` must be in the local chain with `number ≤ Safe` (`-32003`), then the **whole block's** receipts are re-encoded to consensus receipt RLP (legacy `RLP([status, cumulativeGasUsed, logsBloom, logs])`; typed 0x01–0x04 prefixed) and `ordered_trie_root` must equal the sealed `receiptsRoot` — mismatch → `-32001`. Verified: `status`, `cumulativeGasUsed`, `logsBloom`, `type`, and every `logs[]` entry (`address`/`topics`/`data`). **`gasUsed` is derived**, not echoed: `receiptsRoot` binds `cumulativeGasUsed`, and a receipt's own gas is its cumulative total minus the previous receipt's, so the served value is computed from consensus-verified data and an upstream's own `gasUsed` is discarded. Checked against 555 receipts over 10 live mainnet blocks — 0 mismatches. **`transactionHash` is bound** to `transactionsRoot`: the position in the receipt list is the transaction index, so a receipt labelled with another transaction's hash is `-32001` — without this, receipt 5's consensus fields could be served under transaction 2's hash and verify perfectly. **`to`, `from`, `contractAddress` and `effectiveGasPrice` are derived** from the bound envelope rather than echoed — `to` is an RLP field, `from` is recovered from the signature over the envelope, `contractAddress` is `keccak(rlp([sender, nonce]))[12..]` for a creation and `null` for a call, and `effectiveGasPrice` is the legacy `gasPrice` or EIP-1559's `base + min(tip, cap - base)` with the base fee taken from the sealed header. **Nothing on a receipt is echoed from the upstream any more.** All of it holds only when the upstream serves raw envelopes; when it does not (`TxBind::Omitted`) the values are unprovable rather than wrong, so the echoed ones stand rather than failing an otherwise verified read. Checked against geth on live mainnet: 489 receipts over 10 blocks covering all five EIP-2718 types — 0 mismatches on all six fields. `blockHash` / `blockNumber` / `transactionIndex` are overwritten from the local sealed header. Parse caps (violation → `-32001`): `status` ∈ {0,1}, `type` ∈ {0…4}, `logsBloom` 256 bytes, ≤**1024** logs, ≤**4** 32-byte topics per log, `log.data` ≤**64 KiB**, ≤**4096** receipts. Empty `receiptsRoot` → `null`; hash not among the bound receipts → `null`. Pending (null hash+number) and "upstream serves no receipts for the block" fall back to the unverified header-bound passthrough — `--allow-unverified-passthrough` required there (`-32601` otherwise), same field checks as `eth_getTransactionByHash`. |

| `eth_estimateGas` | Verified (constrained, best-effort) | Same policy as `eth_call` (`n ≤ Safe`; `to` + optional `data`; **no create**; **no state overrides**; no `blobVersionedHashes` / `authorizationList`; optional `accessList` prefetch; calldata ≤ **128 KiB**; at most **32** accounts). Never proxied to upstream `eth_estimateGas` / `eth_call`. Unproven SLOAD/account → `-32001`. `BLOCKHASH` from local verified headers (same as `eth_call`). Revert / Halt → JSON-RPC **code 3**. | `eth_getLogs` | Verified | **Ranges up to 128 blocks**: `fromBlock`..`toBlock` (tags → Safe; omitted → Safe) or a single `blockHash`. A wider span is `-32602` and says why; `fromBlock` above `toBlock` is `-32602`; `blockHash` together with `fromBlock`/`toBlock` is `-32602`. Logs are read from each block's `receiptsRoot`-bound receipts (see `eth_getBlockReceipts`), **never** from upstream `eth_getLogs` — a range is many verified single-block answers concatenated, which is why this client can serve spans that public providers refuse with `limit exceeded`. There is no log index, so every block in the span costs one upstream fetch and one verification; that is what the 128-block cap bounds. A block whose receipts the upstream declines is `-32001`, **not** a silently short answer — reporting “no matching logs” for a block nobody checked is a wrong answer, not a partial one. A block proven empty (empty `receiptsRoot`) contributes nothing and is not an error. Results are ascending by block, then by `logIndex`. Filter: `address` 20-byte hex or array of them; `topics` at most **4** positions (`null` wildcard / 32-byte hex / array-of as OR). `logIndex` is the block-wide index; `removed` is always `false`. Result capped at **1024** logs (**silently truncated**, no error). Empty / unavailable receipts → `[]`. `pending` / `earliest` / above Safe / not in the local chain → `-32003`. |
| `eth_newFilter` | Verified | Validated at creation, not at poll time: a malformed `address` or `topics` is `-32602` immediately. `blockHash` is refused — a filter follows a range; use `eth_getLogs` for one block. `fromBlock` fixes the lower bound; an explicit `toBlock` height closes the filter there, while a tag (or omitting it) leaves it following the head. Returns a hex id, sequential per process and never reused. At most **64** live filters, oldest idle one dropped at the cap; a filter idle for **5 min** is forgotten (geth's default) |
| `eth_newBlockFilter` | Verified | Hashes of blocks verified from now on — a fresh filter reports what happens next, not a backlog |
| `eth_getFilterChanges` | Verified | Log filter: matching logs since the last poll, from `receiptsRoot`-bound receipts, then the cursor advances **only over blocks this call read** — a poll that stops at the 128-block cap resumes exactly where it left off, so a caller behind a busy chain catches up over several calls rather than losing the gap. | `eth_getFilterLogs` | Verified | Everything the filter matches over its **whole** range, cursor untouched. A filter whose range has outgrown the 128-block cap is `-32602` naming the span — use `eth_getLogs` with an explicit narrower range. A block filter here is `-32602` |

Remaining (later; **not done**): `eth_subscribe` (needs a WebSocket transport) and pending-transaction filters (no mempool); `gasUsed` — **closed** (derived from the verified cumulative chain). Receipt `transactionHash` bound to `transactionsRoot`; `to`, `from`, `contractAddress` and `effectiveGasPrice` derived from the bound envelope — **closed**, when the upstream serves envelopes. `receiptsRoot` binding on receipts/logs — **closed** (consensus receipt RLP + `ordered_trie_root` vs the sealed header). Single-block `eth_getLogs` — **closed**. `transactionsRoot` hashes in `eth_getBlock*` — **closed** (raw-RLP DeriveSha; omit if no envelopes). `accessList` prefetch is **closed**. Historical `n≤Safe` and the proof-round seed budget are **closed**.

**Which head tags resolve to.** Since 2026-08-25 all of `latest` / `safe` / `finalized` → the **BEP-126 BLS-finalized** head (~2 blocks behind the tip) by default, falling back to the **confirmation-depth Safe** head (~106–113 blocks) whenever no finalized head is known — a checkpoint without BLS vote keys, or a stalled vote round. `run --finality confirmation-depth` pins the older rule. The startup line names which of the two is actually in force. The fast head is used **only** when it is newer than confirmation depth *and* names a block this client verified itself, so enabling the flag can never move reads backwards or onto a block taken on an upstream's word. `helios_bsc_syncStatus.safeSource` reports which rule chose the current head, and `distinctSealers` / `requiredSealers` always describe confirmation depth. The ≥24 h soak covering this head passed 2026-08-24.

Wallet tags: `latest` / `safe` / `finalized` all resolve to the head described above. Hex number or 32-byte hash is allowed for verified state and `eth_getBlock*` iff the block is in the local verified chain and `number ≤ Safe`. `pending` and `earliest` are rejected (`-32003`), not genesis. HTTP is **POST-only**; missing Content-Type is allowed (curl); `application/json` / `json-rpc` / `jsonrequest` ok; `text/html` and form-urlencoded → **415**. Loopback binds also require a loopback `Host` (403 otherwise).

Error codes: `-32700` parse error, `-32600` invalid request (including empty batch, batch > 64, missing/`jsonrpc` ≠ `"2.0"`, `id` not string≤128 / integer / null, fractional `id`, non-graphic method name), `-32602` `params` not an array or more than 16 params, `-32001` proof failed (unproven SLOAD/account/`BLOCKHASH`/budget), `3` `execution reverted` / halt (geth; not `-32001`), `-32002` stateRoot, `-32003` not synced / wallet tag, `-32601` unsupported (also `unverified_passthrough_disabled`), `-32000` upstream unreachable (`unverified_upstream` / `broadcast_failed`; transport, not a trust claim — also what a provider that refuses `eth_getBlockReceipts` or `eth_getRawTransactionByHash` returns, since no answer arrived to find fault with). JSON-RPC **batches** are supported (max 64); notifications (no `id`) are omitted from the batch response; a lone notification is HTTP 204 / JSON `null`.

`--checkpoint` enables sealing-set membership **and** in-turn difficulty. `--oracle` / `helios-bsc soak --min-unique 10` compares MPT balances to an independent host (not the proof upstream). `--backup` / `HELIOS_BSC_BACKUP` is transport failover only (not a trust oracle).
